## О преобразовании личной учётной записи

Преобразование личной учётной записи в организацию позволяет перейти на общую учётную запись, в которой большое количество людей может одновременно сотрудничать над многими проектами. Преобразование вашей учётной записи:
* Сохраняет репозитории в том виде, в котором они есть, без необходимости переносить их в другую учётную запись вручную
* Автоматически приглашает соавторов в команды с разрешениями, эквивалентными их предыдущим разрешениям

При преобразовании личной учётной записи в организацию мы добавим соавторов репозиториев, принадлежащих этой учётной записи, в новую организацию как внешних соавторов. Затем вы сможете пригласить их в команды.

Для преобразования личной учётной записи в организацию см. [AUTOTITLE](/account-and-profile/how-tos/setting-up-and-managing-your-personal-account-on-github/managing-your-personal-account/converting-a-user-account-into-an-organization).

## О перемещении вашей работы в организацию

Вы можете переместить репозитории и проекты из своей личной учётной записи в организацию, сохраняя при этом вашу личную учётную запись. Это позволяет осуществлять командное сотрудничество с детальным контролем разрешений на всей вашей работе.

Дополнительные сведения см. в разделе [AUTOTITLE](/account-and-profile/how-tos/account-management/moving-your-work-to-an-organization).

## Об удалении вашей личной учётной записи

Удаление личной учётной записи удаляет все репозитории, ветки приватных репозиториев, вики, проблемы, запросы на слияние и страницы, принадлежащие вашей учётной записи. {% ifversion fpt or ghec %}Проблемы и запросы на слияние, созданные другими пользователями, будут отделены от вашей учётной записи, но останутся в репозитории.{% endif %}

{% ifversion fpt or ghec %}При удалении вашей учётной записи мы прекращаем выставлять вам счета. Адрес электронной почты, связанный с учётной записью, становится доступным для использования с другой учётной записью. Через 90 дней учётная запись будет полностью удалена из нашей системы.

Если вы единственный владелец организации, вы должны передать права собственности другому человеку или удалить организацию перед удалением личной учётной записи. Если в организации есть другие владельцы, вы можете удалить личную учётную запись без передачи прав собственности на организацию.

## Об отсоединении вашего адреса электронной почты

Поскольку адрес электронной почты может быть связан только с одной учётной записью {% data variables.product.prodname_dotcom %}, если вы потеряли свои учётные данные двухфакторной аутентификации и не можете восстановить доступ, отсоединение адреса электронной почты от вашей учётной записи позволяет связать его с новой учётной записью.

> [!NOTE]
> Предоставленный {% data variables.product.github %} адрес электронной почты `noreply` не может быть отсоединён от учётной записи. Коммиты, написанные с адресом `noreply`, не могут быть переподключены к другой учётной записи.

Имейте в виду, что ничего другого, связанного с вашей учётной записью, заблокированной двухфакторной аутентификацией, включая репозитории, разрешения и профиль, не будет перенесено в вашу новую учётную запись.

Отсоединение адреса электронной почты доступно только для учётных записей с включённой двухфакторной аутентификацией. Если у вас не включена двухфакторная аутентификация, вы можете войти и удалить свой адрес электронной почты из параметров вашей учётной записи.

Образовательные льготы не могут быть перенесены после отсоединения адреса электронной почты и связывания его с другой учётной записью. Чтобы сохранить эти льготы, вы должны продолжать использовать исходную учётную запись, с которой они были связаны.

Для отсоединения адреса электронной почты см. [AUTOTITLE](/free-pro-team@latest/account-and-profile/how-tos/setting-up-and-managing-your-personal-account-on-github/managing-your-personal-account/unlinking-your-email-address).

## Об управлении несколькими учётными записями

В некоторых случаях вам может потребоваться использовать несколько учётных записей на {% data variables.product.github %}. Например, у вас может быть личная учётная запись для вклада в проекты с открытым исходным кодом, а ваш работодатель может также предоставить вам управляемую учётную запись пользователя для работы в {% data variables.product.prodname_dotcom_the_website %}.

Чтобы узнать, как управлять несколькими учётными записями, см. [AUTOTITLE](/free-pro-team@latest/account-and-profile/how-tos/setting-up-and-managing-your-personal-account-on-github/managing-your-personal-account/managing-multiple-accounts).

Вы не можете использовать {% data variables.enterprise.prodname_managed_user %} для вклада в публичные проекты на {% data variables.location.product_location %}, поэтому вы должны вносить вклад в эти ресурсы со своей личной учётной записью.

Если вам нужно использовать несколько учётных записей, вы можете оставаться в системе для своих учётных записей и переключаться между ними. Например, переключение между личной учётной записью и служебной учётной записью. Дополнительные сведения см. в разделе [AUTOTITLE](/authentication/connecting-to-github-with-ssh/managing-deploy-keys).

Если вы хотите использовать одну рабочую станцию для вклада с обеих учётных записей, вы можете упростить вклад с помощью Git, используя комбинацию протоколов для доступа к данным репозитория или используя учётные данные на основе учётной записи.

Git может использовать протокол HTTPS или SSH для доступа и обновления данных в репозиториях на {% data variables.product.github %}. Протокол, который вы используете для клонирования репозитория, определяет, какие учётные данные используются при обновлении с помощью командной строки.

Вы можете найти оба URL-адреса HTTPS или SSH для клонирования репозитория на странице репозитория. Дополнительные сведения см. в разделе [AUTOTITLE](/repositories/creating-and-managing-repositories/cloning-a-repository).

Дополнительные сведения об использовании SSH для доступа к репозиториям см. в разделе [AUTOTITLE](/authentication/connecting-to-github-with-ssh).

> [!WARNING]
> Будьте осторожны при использовании одной рабочей станции для вклада в две отдельные учётные записи. Управление двумя или более учётными записями может увеличить вероятность случайной утечки внутреннего кода в открытый доступ.
